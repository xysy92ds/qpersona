# 一起看视频：更便宜的方案

> 结论：**不要把画面持续喂给 AI**。用「播放器 + 字幕时间轴」当上下文，
> 只在用户提问或偶尔「看一眼」时调用视觉模型。成本能降一到两个数量级，效果反而更好。

## 1. 三种做法

| 方案 | 怎么工作 | 成本 | 体验 |
| --- | --- | --- | --- |
| 屏幕共享 + 连续视觉 | 每几秒截一帧发给视觉模型 | 很高 | 画面延迟、角色只能看到静帧，还容易被 DRM 黑屏 |
| **字幕伴看（推荐）** | 读取字幕，按当前时间给 AI 最近几句台词 | 很低 | AI 知道谁说了什么、剧情到哪，能接梗、能解释 |
| 同步放映 | 真人之间同步播放进度；AI 只读字幕/聊天 | 低 | 适合两个人一起看，AI 当陪看搭子 |

以一部 2 小时电影粗略估算（价格随模型浮动，仅作量级参考）：

- 每 8 秒一帧：约 900 次视觉调用，可能十几到几十元；
- 字幕每 1~2 分钟一段：约 60~120 次文本调用，通常不到一元；
- 只在用户开口时调用：一晚上几毛钱。

## 2. 推荐架构（QPersona 内）

```
视频播放器（本地文件 / 直链 mp4 / iframe）
        │  当前时间
        ▼
字幕解析（.srt / .vtt）→ 最近 N 句 + 前后文
        │
        ▼
调度层：片名 + 简介 + 角色卡 + 字幕上下文 + 记忆
        │
        ▼
角色短评 / 回答（QQ 气泡或侧边栏）
```

要点：

- **只给到当前时间**的字幕，天然防剧透；
- 用户暂停问「刚才那句什么意思」时，把前后 5 句一起给；
- 可选「看一眼」按钮：当前帧走一次 `describeImage()`，用于纯视觉场面；
- 角色可以主动吐槽，但频率由用户设（每 1/2/5 分钟，或只在被问时）。

## 3. 现成的同步放映工具（真人之间）

- **OpenTogetherTube**：开源自建，房间链接、实时同步、聊天，支持 YouTube / Vimeo /
  HTTP mp4 / HLS / DASH。功能列表见 [GitHub](https://github.com/dyc3/opentogethertube)。
- **Syncplay**：桌面端同步 mpv / VLC / MPC 的播放进度，Apache-2.0，适合本地片源；
  不做文件分享。见 [GitHub](https://github.com/Syncplay/syncplay)。
- **Jellyfin / Plex**：如果已经有媒体服务器，自带同步放映，不用另搭。
- **Teleparty / Watch2Gether**：商业服务，适合流媒体平台，但 AI 接不进去。

如果是「一个人 + AI 看」，**不需要任何同步服务**，播放器和聊天共用一个时钟即可。
如果是「两个人 + AI」，建议用 OTT/Syncplay 同步真人，AI 挂在其中一端的字幕上。

## 4. 落进项目的步骤

1. `WatchPage.vue`：本地文件选择或直链播放，`<video>` + 时间轴；
2. `subtitle.ts`：解析 srt/vtt，`linesAt(t)` 返回最近 N 句；
3. 调度：新增 `watch` 场景提示词（短评、别剧透、可以吐槽），复用 `text_main`；
4. 聊天侧栏/气泡：角色按设定发言，支持暂停提问；
5. 可选：单帧视觉、多人同步（PeerJS data channel 广播 play/pause/seek）。

## 5. 容易踩的坑

- **字幕对不上片源**：不同版本的偏移几秒，提供 ± 偏移调节；
- **剧透**：永远只取 `t <= 当前时间` 的字幕；用户主动问后续才给；
- **DRM**：Netflix 等受保护内容截不了图，也不该抓；只支持用户自己的文件/公开直链；
- **版权**：项目不提供片源，不下载、不转存；
- **移动端**：后台播放、画中画、自动播放限制要单独处理；
- **成本**：主动评论频率默认低，用户可调；每轮把字幕截断到最近 30 句，避免上下文膨胀。

## 6. 和「视频通话/屏幕共享」的关系

- 屏幕共享是**实时**看你在做什么；一起看视频是**长时间、低成本**的陪伴，两者不是一回事。
- 屏幕共享按帧看，适合短时间；看电影两小时用字幕，钱包和体验都更稳。
- 如果以后做「AI 陪看直播」，再考虑低频截帧 + 聊天室文本，仍然不建议连续视觉。
