# 语音通话与屏幕共享：怎么接、先接哪一段

> 状态：**与 AI 的语音通话已实现**（0.11.0，半双工、按住说话）；屏幕共享仍是方案。
> 真人好友**目前只支持文字消息**（云端中转、保留 7 天）；真人语音/视频通话（RTC）**尚未实现**。
> 下面「和 AI 通话」的链路不涉及第二个真人，不代表项目没有真人好友。

## 1. 先分清两种通话

**和 AI 通话**
这条链路里没有第二个真人参与，不需要 WebRTC。链路是：

```
麦克风 → VAD / 按住说话 → STT → 文本模型 → TTS → 扬声器
```

**和真人 / 另一台设备通话**
才需要 WebRTC（点对点或 SFU）。项目已有**文字版真人好友**，但真人语音/视频通话没有做；
如果以后要做，建议直接接 LiveKit 或 PeerJS 的信令，不自己写 SDP/ICE。

## 2. 和 AI 通话：第一版（半双工）

### 交互

- 通话页：对方头像、通话计时、静音、扬声器、挂断。
- 按住说话（PTT）优先，VAD 作为第二版：
  - PTT：按下开始录音，松开结束，转写后提交一轮。
  - VAD：用能量阈值 + 300ms 静音断句，自动提交。
- 回复播放时不允许打断（半双工）；后续再做 barge-in。

### 链路

1. **录音**：`getUserMedia({audio:true})` + `MediaRecorder`（已有语音消息的实现可直接复用）。
2. **STT**：优先用 `stt` 槽位（OpenAI `/audio/transcriptions`，multipart 上传）；
   没配置时回落到浏览器 `SpeechRecognition`（中文可用，但只能实时听，不能传文件）。
3. **文本**：复用 `text_main`，上下文用最近 20 轮 + 记忆；提示词加一条「这是语音通话，回复要更短、更口语」。
4. **TTS**：优先用 `tts` 槽位（OpenAI `/audio/speech`，返回 mp3）；
   没配置时用 `SpeechSynthesis`（现在「朗读」按钮已经在用）。
5. **播放**：`new Audio(url)` 或 `audio.play()`；播放结束回到待机。

### 需要新增的槽位调用

`src/core/audio.ts` 里加两个函数：

```ts
transcribe(profile, blob): Promise<string>       // POST /audio/transcriptions, model=whisper-1
synthesize(profile, text): Promise<Blob>         // POST /audio/speech, voice 可配置
```

都是 OpenAI 兼容格式；`stt` / `tts` 留空就走浏览器能力，保证零配置能用。

### 成本与体验控制

- 每轮最长 30 秒录音，超时自动停止。
- 连续 5 轮无语音输入 → 自动挂断提示。
- 通话页显示本轮 token / 花费（复用现有 usage）。
- 全局「语音播报」和角色「主对话」开关在通话里同样生效。

## 3. 屏幕共享：让 AI「看一眼屏幕」

不需要 WebRTC，也不需要持续推流：

1. `getDisplayMedia({video:true})` 拿到屏幕流。
2. 用隐藏的 `<video>` 播放，按需 `drawImage` 到 canvas。
3. 截帧策略：默认每 8 秒一帧，或用户点「让 TA 看看」时立刻截一帧。
4. 压到 1280px、JPEG 0.72，发给 `vision` 槽位描述：
   - 有 vision 槽位：`describeImage()` 生成描述。
   - 主模型支持图片：直接作为多模态内容发送。
5. 描述以「[屏幕：用户正在看……]」注入对话，由角色自然接话。
6. 顶部常驻「正在共享屏幕」提示，随时停止；不录像、不落盘原图。

### 隐私

- 共享前弹一次确认，说明「会截取当前屏幕并发送给你配置的视觉模型」。
- 只截应用窗口/整个屏幕由系统选择器决定；不读取剪贴板、不监听键盘。
- 停止共享立即停止截帧；关闭开关不保留任何帧。

### 成本

- 每帧一次 vision 调用；8 秒一帧、一分钟 7~8 次，费用取决于视觉模型单价。
- 提供「仅在问我时看一眼」模式，默认每 8 秒自动看一眼可以关。

## 4. 如果要接真人通话（后续，未实现）

- 真人好友目前只有文字：语音/视频通话（RTC）**未实现**，也没有入口；
- 要做得加 WebRTC + LiveKit/PeerJS 信令；音频轨直接互通，AI 可以作为第三个参与者加入房间。
- 需要服务器或 TURN，和「本地优先」定位有冲突，所以排在后面。
- 屏幕共享同理：真人看屏幕走 WebRTC，AI 看屏幕走截帧 + vision。

## 5.5 实现备注（语音通话 0.11.0）

- 聊天页右上角电话按钮打开通话页；按住说话 → 松开提交；
- 配置了「语音识别」槽位就用 `MediaRecorder` + `/audio/transcriptions`；
  没配置就用浏览器 `SpeechRecognition`；
- 配置了「语音合成」槽位就用 `/audio/speech`，否则用 `SpeechSynthesis`；
- 通话轮次写进聊天记录（带「语音通话」提示词），挂断后留一条时长提示；
- 语音适配器测试见 `scripts/audio-smoke.ts`，端到端用假麦克风跑过。

## 6. 现状与限制

- `stt` / `tts` / `vision` 槽位和 OpenAI 兼容适配器已在用，语音通话与语音消息共用；
- 通话是半双工：回复播放时不能打断；还没有 VAD 自动断句，靠按住说话；
- 通话轮次会写进聊天记录与记忆；
- 真人好友只能发文字，不能发起语音通话；屏幕共享、一起看视频都还没有入口。
