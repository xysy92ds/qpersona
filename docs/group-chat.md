# 群聊：兴趣值 + 激活/屏蔽 的落地方案

> 状态：v0.23.0。**AI 角色群聊**已落地：建群、激活、5 分钟活跃窗口、多人顺序回复、群设置、
> 收件人/回复关系、整轮上下文与「可跳过」；与设计稿的差异见文末「实现备注」。
> **真人 + AI 共享群聊已接入（部分支持）**：建群可选真人好友（需登录云端账号且互为好友），
> 云端建群、群消息各端轮询、真人成员可收发；限制见 §12。
> 原则：**屏蔽状态下零模型调用**；先保证「不烧钱、不乱说话」，再谈热闹。

## 1. 要解决的问题

把多个 AI 角色（以及真人好友）拉进一个群，如果每条消息都让所有角色各回一次：

- 成本按人数线性增长，5 个角色聊 10 轮 = 50 次请求；
- 角色会抢话、复读，群聊变成「多个客服轮流发言」；
- 上下文爆炸，每个角色都要读全群记录。

所以核心不是「让谁说话」，而是**让不该说话的人保持沉默，而且沉默不花钱**。
真人成员本身不跑模型；他们发的消息会像用户消息一样参与激活打分，由握着角色卡的客户端生成 AI 回复（见 §12）。

## 2. 数据模型

复用现有 `Conversation`，新增 `kind: 'group'` 和 `memberIds`：

```ts
interface Conversation {
  kind: 'group'
  title: string
  memberIds: string[]
  group?: {
    maxSpeakers: number      // 每条用户消息最多几个人回，默认 2
    cooldownSec: number      // 同一个人两次发言的最小间隔，默认 90
    interestEnabled: boolean // 软触发开关
  }
}
```

每个成员在群里的状态单独一张表，避免塞进角色卡：

```ts
interface GroupMemberState {
  id: string            // `${conversationId}:${characterId}`
  conversationId: string
  characterId: string
  seenTs: number        // 这个角色「已经看到」到哪里
  lastActiveAt: number  // 上次发言时间
  mutedUntil: number    // 用户手动屏蔽到什么时候（0 = 不屏蔽）
  speakCount: number    // 本群发言次数，用于冷启动轮换
}
```

消息已经有 `characterId`，群聊里直接用它区分谁说的；用户消息为 `undefined`（显示为「你」）。

真人群聊的会话额外存云端群字段：`serverGroupId / serverGroupOwnerId / serverGroupSince`
（纯本地 AI 群为空）；从云端群组合成进来的「其他设备的 AI 成员」用
`ext.remoteBot = { groupId, botId }` 标记，本机不为它跑模型。

## 3. 激活算法（先纯规则，零模型）

用户发一条消息后：

1. **硬触发**
   - 文本包含 `@昵称` 或 `@别名`（`ext.qq.aliases`）→ 该角色 +100。
   - 文本包含角色名/别名（无 @）→ +30。
2. **软触发**（`interestEnabled`）
   - `ext.qq.interests` 里的词出现在消息中 → 每个 +8。
   - 与角色最近 3 条群消息做中文二元组重合 → 每次命中 +1，最多 +6。
3. **状态修正**
   - `mutedUntil > now` → 直接排除（用户屏蔽优先）。
   - `now - lastActiveAt < cooldownSec * 1000` → -40（刚说过话的人先歇会儿）。
   - 本群发言次数越少 → +最多 10（防止一个人一直霸屏）。
   - 加 0~3 的随机抖动，避免每次都是同一个人。
4. **选取**
   - 得分 ≥ 20 的角色按分数排序，取前 `maxSpeakers` 个。
   - 被 @ 的人必定入选，且优先。
   - 一个都没有 → **不调用任何模型**，只落库消息。

真人成员不参与打分、也不跑模型：群主客户端轮询到真人新消息后，把这条消息当成「最后一句」
跑上面的激活流程，再决定要不要让 AI 接话（见 §12）。

> 实现取值与设计稿不同：阈值取 **15**、单次最多 **2 人**、冷却 **1.5 秒**（设计稿里的 20 /
> `maxSpeakers` / 90 秒是初版设想），详见 §11。

## 4. 发言与上下文隔离

选中的角色按顺序（间隔 600~1200ms）发言，每个角色：

- 读取自己 `seenTs` 之后的群消息（最多 30 条），加上群设定和成员名单；
- 注入自己的长期记忆（复用单聊的记忆库，`characterId` 相同，`conversationId` 指向群）；
- 生成后更新 `seenTs`、`lastActiveAt`、`speakCount`；
- 失败或超时不阻塞其他人（逐个 try/catch）。

这样每个角色只「记得」自己在群里看到和说过的部分，不会出现全员共享上帝视角。

## 5. 群聊提示词

单独一份 `groupSystem`，不复用短消息单聊：

- 群里不止你一个人，可以附和、可以怼、可以只回一两个字；
- 不要每句都接最后一个人，允许冷场；
- 不要复述别人刚说过的话；
- 一次 1~2 条，别刷屏；
- 名单里标出「谁刚说过话」「谁被 @ 了」；
- 群成员名单（`群里还有：…`）只列 AI 角色；真人好友以「群聊记录」里正常发送者的身份出现，
  不需要让模型知道谁是机器人、谁是真人。

模型输出仍按换行拆气泡，但**同一个角色连续多条**只算一次发言。

## 6. UI

- 新建群：从联系人里多选 ≥2 人，起群名；成员可以是 AI 角色，也可以是真人好友。
  只选 AI 角色时是纯本地群（不用登录）；选了真人好友就要求已登录云端账号，建群会调用云端群组接口。
- 群聊页：复用 `ChatPage`，消息上方显示昵称（`showName` 已支持），头像按 `characterId` 取；
  真人和 AI 的消息混排。
- 输入框 `@` 弹成员选择；发送后按激活结果逐个「正在输入…」。
- 群设置：成员管理、每个人单独屏蔽、兴趣开关、最多回几个人。真人群的群名/头像/成员增删只改本机，
  不会同步给云端其他成员（MVP 没有成员管理 API）。
- 群会话列表里显示「N 人群」。

## 7. 成本与安全阀

- 全局：`settings.flags.groupInterest` 关闭后，只响应 @ 和叫名字。
- 每组：`maxSpeakers` 上限（默认 2）、`cooldownSec`。
- 每个角色：已有的「主对话」开关同样生效，关闭后不参与。
- 失败重试：不自动重试，避免重复扣费。
- 云端群：服务端不做群内频率限制、也不校验 AI 消息真伪；模型费用仍只发生在跑模型的那台客户端上。

## 9. 测试

- 纯函数测激活打分：@ 必中、屏蔽不出、冷却降权、无命中零调用。
- 假模型 E2E：两个角色，一个被 @，断言只发一次请求、另一人零请求。
- 长会话：连续 20 条无关消息，断言没有模型请求（成本为 0）。

## 10. 已知取舍

- 不做「所有人同时生成再择优」，那样成本翻倍且难控制。
- 不做实时打断/抢话，第一版按顺序发言，靠间隔和随机降低机械感。
- 群记忆先复用单聊记忆表，后续再决定是否拆分「群内记忆 / 私聊记忆」。
- 真人群聊先保证「能收发、能持久化」：不做成员管理、不做服务端推送、AI 只在握着角色卡的那台
  客户端上生成；这些是刻意留到后面的，不是遗漏。


## 11. 实现备注（0.10.0 ~ v0.23.0）

已实现：

- 建群页 `/group/new`：多选好友、群名、至少两人；联系人页和「+」菜单都可进入。
- 激活：`src/core/group.ts`，@ / 别名 / 名字 / 兴趣 / 冷却 / 随机；阈值 15，最多 2 人。
- 群聊请求：`buildGroupMessages` 把最近 30 条压成「群聊记录」，避免用 user/assistant 表达多人对话。
- 发言顺序：选中的角色逐个流式回复，间隔 320ms；每个角色单独算 token 与花费。
- **活跃窗口**：被叫到的人写入 `activeUntil = now + 5 分钟`（群设置可改 1/3/5/10/30），
  窗口内即使没被再次叫到也会接话（1.5 秒冷却、最多两人）；发一句就续 5 分钟，窗口过期后完全静默。
- **@ 选择器**：输入 `@` 浮出成员列表，点选插入 `@昵称 `；「更多 → 提到成员」也可用。
- **群设置**：群名、群头像、成员增删、唤醒时长、严格上下文隔离（默认关）、成员免打扰，
  路由 `/group/:id/info`。
- **收件人/轮次**：用户消息解析 @、引用、名字，得到「谁 → 谁」；回复带 `roundId / replyToId /
  addressees`。默认让角色读自己被唤醒后整轮所有人的发言，再决定回不回；不想接输出 `[跳过]`。
- 零调用：没有任何人达到阈值、也没有活跃成员时，`respondGroup` 直接返回，不请求模型。
- **真人成员（v0.23.0 起）**：建群页可选真人好友；含真人的群走云端群组接口（`serverGroupId`），
  真人和 AI 消息混排在同一个会话里；纯 AI 群仍是本地群，不需要登录。真人会话本身仍只支持文字。
- **云端群同步（v0.23.0）**：`src/core/groups.ts` + `src/store/groups.ts`；App 前台每 10 秒轮询
  群列表和 `GET /api/groups/:id/messages?since=`，把别人的消息写进本地会话；自己发的文字和
  AI 发言会 POST 回服务端。群消息只同步文字，图片/表情/文件/语音在群里只本机可见。

和设计稿的偏差（后续补）：

- 上下文隔离已做（可关）：每个成员只读自己 `seenTs` 之后 + 最近 10 条；
- `maxSpeakers` 可调还没做；
- 没有持久化 `GroupMemberState`，冷却只按「最近 4 条里谁说过话」粗略计算；
- 群记忆已和私聊打通：记忆按角色存，群聊总结带 `source='group'`，召回时标 `[群聊]`；
  群设置可关闭「私聊记忆进群」。仍复用同一张记忆表，不做「群内 / 私聊」物理拆分。

手动验证（Playwright + 假接口）：

- `@知夏 在吗` → 只发 1 次请求，知夏回复；
- `嗯嗯` → 0 次请求；
- `有人要喝咖啡吗` → 只叫醒周屿（兴趣：咖啡）；
- 双击周屿头像 → 出现「你拍了拍周屿」；
- `@` 弹出成员列表，选中后发消息 → 1 次请求；4.5 秒后再发一句无关的话 → 活跃成员继续回（2 次）；
- 清空 `groupActive` 模拟 5 分钟过期 → 再发「嗯嗯」→ 0 次请求。


## 12. 真人 + AI 共享群聊（部分支持，已可用）

状态：**已接入，可按「部分支持」使用**。后端与前端都已实现；下列限制还在，别把 MVP 写成完整群功能。

已实现：

- 建群页可选真人好友（`ext.human`），选中真人时要求已登录云端账号：`POST /api/groups`
  校验对方是好友后建群，owner 自动入群；纯 AI 群不需要登录，仍是本地群。成员可以全是真人
  （纯云端文字群、不产生模型调用），也可以真人与 AI 混排；
- 群组、成员、AI 展示元数据、群消息存在 D1 的 `groups / group_members / group_bots /
  group_messages`；云端**不存模型 Key**，AI 消息只回传文字；
- App 前台每 10 秒轮询群列表 + `GET /api/groups/:id/messages?since=`（默认 100 条、最多 500）；
  别人的消息按 `serverGroupSince` 增量写入本地会话，`serverId` 用于去重；自己发的文字和 AI 发言
  POST 回服务端；
- 真人消息在本地按「群成员」渲染，AI 消息按 `botId` 找回登记的 AI 角色卡；真人与 AI 混排；
- 群消息只同步文字：图片 / 表情 / 文件 / 语音在群里只本机可见，其他成员看不到；
- 服务端限额：真人成员 50（含 owner）、AI 成员 20、群名 40 字、消息 4000 字、AI 头像 40000 字符；
  群列表最多 100 个。

已知限制（MVP）：

- **没有成员管理**：无退群 / 移除成员 / 改名 / 群主转让；群设置里的群名、头像、成员增删只改本机，
  不会同步给其他成员；云端群名只认建群时的名字；
- **没有服务端推送**：群消息靠前端轮询（约 10 秒，App 打开时）；Android 常驻通知只轮询好友私聊，
  群消息没有后台通知；群主那台客户端不在线时 AI 不会回复，等它下次打开 App 轮询到新消息再补生成；
- **AI 由本机生成**：只有建群时登记 AI 角色卡的那台客户端会在本机跑模型，用本机的模型 Key；
  其他设备/成员收到的是 `ext.remoteBot` 标记的 AI 展示元数据，不在本机跑模型；
- **服务端不校验 AI 消息真伪、不做群内频率限制**：任何群成员理论上都能替已登记的 AI 发消息；
- 群消息走独立接口，不进 `/api/sync` 备份；群聊数据目前也不参与 30 天不活跃清理。

后端 API、消息结构与部署细节以 [cloud.md](cloud.md) 为准；README 功能矩阵按「部分支持（已可用）」标注。
