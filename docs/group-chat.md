# 群聊：兴趣值 + 激活/屏蔽 的落地方案

> 状态：MVP 已实现（0.7.0）。建群、激活、多人顺序回复、成本上限已落地；
> 与设计稿的差异见文末「实现备注」。
> 原则：**屏蔽状态下零模型调用**；先保证「不烧钱、不乱说话」，再谈热闹。

## 1. 要解决的问题

把多个 AI 角色拉进一个群，如果每条消息都让所有角色各回一次：

- 成本按人数线性增长，5 个角色聊 10 轮 = 50 次请求；
- 角色会抢话、复读，群聊变成「多个客服轮流发言」；
- 上下文爆炸，每个角色都要读全群记录。

所以核心不是「让谁说话」，而是**让不该说话的人保持沉默，而且沉默不花钱**。

## 2. 数据模型

复用现有 `Conversation`，新增 `kind: 'group'` 和 `memberIds`：

```ts
interface Conversation {
  kind: 'group'
  title: string
  memberIds: string[]
  group?: {
    maxSpeakers: number      // 每条用户消息最多几个人回，默认 2
    cooldownSec: number      // 同一个人两次发言的最小间隔，默认 90
    interestEnabled: boolean // 软触发开关
  }
}
```

每个成员在群里的状态单独一张表，避免塞进角色卡：

```ts
interface GroupMemberState {
  id: string            // `${conversationId}:${characterId}`
  conversationId: string
  characterId: string
  seenTs: number        // 这个角色「已经看到」到哪里
  lastActiveAt: number  // 上次发言时间
  mutedUntil: number    // 用户手动屏蔽到什么时候（0 = 不屏蔽）
  speakCount: number    // 本群发言次数，用于冷启动轮换
}
```

消息已经有 `characterId`，群聊里直接用它区分谁说的；用户消息为 `undefined`（显示为「你」）。

## 3. 激活算法（先纯规则，零模型）

用户发一条消息后：

1. **硬触发**
   - 文本包含 `@昵称` 或 `@别名`（`ext.qq.aliases`）→ 该角色 +100。
   - 文本包含角色名/别名（无 @）→ +30。
2. **软触发**（`interestEnabled`）
   - `ext.qq.interests` 里的词出现在消息中 → 每个 +8。
   - 与角色最近 3 条群消息做中文二元组重合 → 每次命中 +1，最多 +6。
3. **状态修正**
   - `mutedUntil > now` → 直接排除（用户屏蔽优先）。
   - `now - lastActiveAt < cooldownSec * 1000` → -40（刚说过话的人先歇会儿）。
   - 本群发言次数越少 → +最多 10（防止一个人一直霸屏）。
   - 加 0~3 的随机抖动，避免每次都是同一个人。
4. **选取**
   - 得分 ≥ 20 的角色按分数排序，取前 `maxSpeakers` 个。
   - 被 @ 的人必定入选，且优先。
   - 一个都没有 → **不调用任何模型**，只落库消息。

## 4. 发言与上下文隔离

选中的角色按顺序（间隔 600~1200ms）发言，每个角色：

- 读取自己 `seenTs` 之后的群消息（最多 30 条），加上群设定和成员名单；
- 注入自己的长期记忆（复用单聊的记忆库，`characterId` 相同，`conversationId` 指向群）；
- 生成后更新 `seenTs`、`lastActiveAt`、`speakCount`；
- 失败或超时不阻塞其他人（逐个 try/catch）。

这样每个角色只「记得」自己在群里看到和说过的部分，不会出现全员共享上帝视角。

## 5. 群聊提示词

单独一份 `groupSystem`，不复用 QQ 单聊：

- 群里不止你一个人，可以附和、可以怼、可以只回一两个字；
- 不要每句都接最后一个人，允许冷场；
- 不要复述别人刚说过的话；
- 一次 1~2 条，别刷屏；
- 名单里标出「谁刚说过话」「谁被 @ 了」。

模型输出仍按换行拆气泡，但**同一个角色连续多条**只算一次发言。

## 6. UI

- 新建群：从联系人里多选 ≥2 人，起群名，自动生成群头像（成员头像拼图）。
- 群聊页：复用 `ChatPage`，消息上方显示昵称（`showName` 已支持），头像按 `characterId` 取。
- 输入框 `@` 弹成员选择；发送后按激活结果逐个「正在输入…」。
- 群设置：成员管理、每个人单独屏蔽、兴趣开关、最多回几个人。
- 群会话列表里显示「N 人群」。

## 7. 成本与安全阀

- 全局：`settings.flags.groupInterest` 关闭后，只响应 @ 和叫名字。
- 每组：`maxSpeakers` 上限（默认 2）、`cooldownSec`。
- 每个角色：已有的「主对话」开关同样生效，关闭后不参与。
- 失败重试：不自动重试，避免重复扣费。

## 9. 测试

- 纯函数测激活打分：@ 必中、屏蔽不出、冷却降权、无命中零调用。
- 假模型 E2E：两个角色，一个被 @，断言只发一次请求、另一人零请求。
- 长会话：连续 20 条无关消息，断言没有模型请求（成本为 0）。

## 10. 已知取舍

- 不做「所有人同时生成再择优」，那样成本翻倍且难控制。
- 不做实时打断/抢话，第一版按顺序发言，靠间隔和随机降低机械感。
- 群记忆先复用单聊记忆表，后续再决定是否拆分「群内记忆 / 私聊记忆」。


## 11. 实现备注（0.7.0）

已实现：

- 建群页 `/group/new`：多选好友、群名、至少两人；联系人页和「+」菜单都可进入。
- 激活：`src/core/group.ts`，@ / 别名 / 名字 / 兴趣 / 冷却 / 随机；阈值 15，最多 2 人。
- 群聊请求：`buildGroupMessages` 把最近 30 条压成「群聊记录」，避免用 user/assistant 表达多人对话。
- 发言顺序：选中的角色逐个流式回复，间隔 320ms；每个角色单独算 token 与花费。
- 零调用：没有任何人达到阈值时，`respondGroup` 直接返回，不请求模型。

和设计稿的偏差（后续补）：

- **上下文还是共享的**：所有成员都能看到全部群消息，没有按成员 `seenTs` 隔离；
- 没有群设置页、单成员屏蔽、`maxSpeakers` 可调；
- 没有持久化 `GroupMemberState`，冷却只按「最近 4 条里谁说过话」粗略计算；
- 群记忆复用单聊记忆库，未按「群内 / 私聊」拆分。

手动验证（Playwright + 假接口）：

- `@知夏 在吗` → 只发 1 次请求，知夏回复；
- `嗯嗯` → 0 次请求；
- `有人要喝咖啡吗` → 只叫醒周屿（兴趣：咖啡）；
- 双击周屿头像 → 出现「你拍了拍周屿」。
